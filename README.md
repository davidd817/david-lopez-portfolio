# David López Diego — Scientific Portfolio

This repository contains David López Diego’s professional scientific portfolio. It presents work in physics, materials characterisation and metrology, nanomaterials, scientific instrumentation, advanced characterisation and reproducible scientific data analysis. Software development supports that scientific profile; it is not the primary professional positioning.

## Technology and architecture

- Next.js 14 with the App Router
- TypeScript with strict checking
- Tailwind CSS 3
- Content-driven, static-friendly pages with no database or CMS
- Local CV and project assets under `public/`
- Metadata, Open Graph, robots, sitemap and Schema.org JSON-LD generated by the App Router

The home page is composed from reusable components in `components/`. Selected-work pages are generated from typed records in `data/work/` and rendered at `/work/[slug]`.

## Local development

```bash
npm ci
npm run dev
```

Open <http://localhost:3000>.

Available quality and production commands:

```bash
npm run lint
npm run typecheck
npm run build
npm run start
```

`npm run start` serves the result of a successful production build.

## Where to edit content

- `data/site.ts`: profile, roles, experience, education, skills, publications and external links
- `data/work/*.ts`: selected-work case studies, metadata, figures and project links
- `components/`: presentation and interaction logic
- `app/layout.tsx`, `app/robots.ts` and `app/sitemap.ts`: site metadata and crawl configuration

Do not add or rewrite professional, scientific or publication claims without source evidence. Preserve the existing scientific positioning and terminology unless a factual correction is explicitly supported.

## CV and assets

The public CV is `public/cv/David_Lopez_Diego_CV_Optimized_B.pdf`. Existing CV links depend on that path; replace the file at the same path when updating it.

Project figures are stored under `public/images/work/` and referenced by typed asset records in `data/work/`. Keep meaningful English alternative text, captions and provenance for new figures. Verify local paths before opening a pull request.

## Deployment

The repository is intended for deployment through Vercel. Vercel should build the repository from the selected Git branch; this repository does not contain deployment workflows or production configuration. Do not add secrets, environment variables, domains or Vercel settings here.

## Project structure

```text
app/          App Router routes, global styles and crawl metadata
components/   Reusable page, navigation and case-study components
data/         Typed professional and selected-work content
docs/         Content and implementation reference material
public/       CV and image assets
types/        Shared TypeScript models
.github/      Pull-request CI and contribution guidance
```

## Maintenance

Keep changes small and reviewable. Before handoff, run lint, typecheck, build and `git diff --check`, inspect the complete diff, and confirm the current branch and professional content are unchanged unless the task explicitly requires otherwise. Pull requests are validated by the workflow in `.github/workflows/ci.yml`.
